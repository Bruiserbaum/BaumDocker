# RustDesk Server

Self-hosted remote desktop relay and ID server. Clients connect to your server instead of RustDesk's public infrastructure — fully private, no account required.

**Source:** [github.com/rustdesk/rustdesk-server](https://github.com/rustdesk/rustdesk-server)

## Services

| Service | Ports | Description |
|---------|-------|-------------|
| **hbbs** | 21115 TCP, 21116 TCP+UDP, 21118 TCP | ID/rendezvous server — device registration and peer discovery |
| **hbbr** | 21117 TCP, 21119 TCP | Relay server — proxies traffic when direct P2P is unavailable |

Both services share a volume so `hbbr` can read the key pair generated by `hbbs`.

## Setup

### 1. Configure `.env`

| Variable | Description | Default |
|----------|-------------|---------|
| `DOMAIN` | Public hostname or IP clients will connect to | `rustdesk.yourdomain.com` |
| `FAST_NODE` | Swarm node to pin the stack to | `TuringPiRK1` |

### 2. Open firewall/router ports

All five ports must be reachable from the internet (or your LAN, for internal-only use):

| Port | Protocol | Service |
|------|----------|---------|
| 21115 | TCP | hbbs NAT traversal test |
| 21116 | TCP + UDP | hbbs peer registration and hole-punching |
| 21117 | TCP | hbbr relay |
| 21118 | TCP | hbbs WebSocket clients |
| 21119 | TCP | hbbr WebSocket relay |

### 3. Start

```bash
docker compose up -d
```

On first start `hbbs` generates an Ed25519 key pair (`id_ed25519` and `id_ed25519.pub`) in the shared volume. `hbbr` reads the public key from the same volume. Allow 5-10 seconds for both services to start before connecting.

### 4. Get your public key

```bash
docker exec $(docker ps -qf name=rustdesk_hbbs) cat /data/id_ed25519.pub
```

Copy this key — you'll paste it into every RustDesk client under **Settings → Network → Key**.

---

## Configuring RustDesk Clients

In the RustDesk app go to **Settings → Network** (unlock with the padlock if needed):

| Field | Value |
|-------|-------|
| ID Server | `rustdesk.yourdomain.com` |
| Relay Server | `rustdesk.yourdomain.com` |
| API Server | *(leave blank)* |
| Key | *(paste content of `id_ed25519.pub`)* |

Restart the RustDesk client after saving. The device ID displayed on the main screen confirms registration with your server.

---

## Volumes

| Volume | Purpose |
|--------|---------|
| `rustdesk-data` | Key pair (`id_ed25519`, `id_ed25519.pub`) and server state — shared by both hbbs and hbbr |

> **Back up `rustdesk-data`.** If the key pair is lost, all existing client configurations (ID server key) will stop working and every client will need reconfiguring.

## Deploying via Portainer

1. Go to **Stacks → Add stack → Repository**
2. Fill in:

| Field | Value |
|-------|-------|
| Repository URL | `https://github.com/Bruiserbaum/BaumDocker` |
| Repository reference | `refs/heads/master` |
| Compose path | `rustdesk/docker-compose.yml` |

3. Under **Environment variables**, add `DOMAIN` and optionally `FAST_NODE`
4. Click **Deploy the stack**
